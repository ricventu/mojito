# Cut-over Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v2 replaces v1: v1's code leaves the tree, every "2" is dropped, `v2` becomes `main`, the box serves v2 as `mojito.service` on 8700 at `/`.

**Architecture:** Three commits on `v2` (remove v1, rename, docs), then a fixed sequence of operations on the box (git, build, service switch, Tailscale, data, worktree).

**Tech Stack:** pnpm workspace, systemd --user, Tailscale Serve, git.

**Spec:** `docs/superpowers/specs/2026-10-30-cut-over-design.md`

## Global Constraints

- Work only in `~/code/mojito-v2` until Task 4; never touch `~/code/mojito`'s files except through git in Task 4.
- Every commit is green: tests, typecheck, build.
- Never touch tmux sessions other than through the service (the box runs live agents).
- Copy, code and docs in English.

## Review Focus

- `.env.local` carries `MOJITO_PORT=8700`: `pnpm dev`'s server must still land on 3100 (the caller's environment wins) — pinned in Task 2.
- A key in `.env.local` must still be scrubbed from children after the rename (`MOJITO_` prefix) — the existing childEnv tests, updated in Task 2.
- A frozen install from the regenerated lockfile must succeed in a clean checkout — Task 1 runs it.
- The built server must start from `~/code/mojito` with no `Environment=` port — Task 4 health check.
- No v2 source may import anything from the removed root (`src/`, root tsconfig) — Task 1's typecheck and build.
